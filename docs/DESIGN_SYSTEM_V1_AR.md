# Krotak Admin Design System v1.0 — سجل التنفيذ

**الحالة:** مطبَّق على الواجهة الحالية في هذه الدفعة، بتركيز كامل على تجربة الهاتف.
**النطاق:** طبقة العرض فقط. لم تُغيَّر أي واجهة API، ولا منطق أعمال، ولا صلاحيات، ولا مصادقة، ولا بيانات.

## 1) قرارات المالك المحسومة

| القرار | التنفيذ |
| --- | --- |
| الخط | بقي **Tajawal** كما هو. لم يُضف IBM Plex Sans Arabic ولم تُغيَّر طريقة تحميل الخطوط. |
| أولوية التصميم | الهاتف أولاً: شريط التنقل السفلي، النوافذ السفلية، مسارات اللمس، والاستجابة. |
| الأولوية الوظيفية | السلاسة وسرعة الاستجابة: بلا blur ثقيل، وبلا ظلال متحركة، وحركة transform/opacity فقط. |
| الهوية | الألوان الستة معرّفة مركزياً وتُستهلك عبر متغيرات `--ui-*` أو طبقة Tailwind. |

## 2) المصدر المركزي للتوكنات

المصدر الوحيد في CSS هو كتلة `:root` واحدة في `src/index.css`. القيم نفسها متاحة في `tailwind.config.js` للأدوات المستخدمة داخل الصفحات (`bg-brand`, `text-forestGreen` ...).

| التوكن | القيمة | الاستخدام |
| --- | --- | --- |
| `--ui-forest-black` | `#051F20` | القائمة الجانبية، شريط التنقل السفلي، خلفية شريط النظام |
| `--ui-deep-forest` | `#0B2B26` | تدرجات الأسطح الداكنة |
| `--ui-forest-green` | `#163832` | العناوين الداكنة، حالة hover للأزرار الأساسية |
| `--ui-primary-green` | `#235347` | الأزرار الأساسية، الروابط، التحديد |
| `--ui-sage-green` | `#8EB69B` | المؤشرات والحدود والحواف (ليس لون نص على أبيض) |
| `--ui-mint-surface` | `#DAF1DE` | الأسطح المحددة والرقائق النشطة |

الأسماء القديمة `--ui-brand`, `--ui-brand-deep`, `--ui-brand-soft`, `--ui-brand-tint` بقيت كأسماء مستعارة للتوكنات الجديدة، لذلك لا تحتاج الصفحات الحالية إلى تعديل.

## 3) الحركة

- `--ui-motion-fast: 120ms` للأزرار والأيقونات.
- `--ui-motion-base: 160ms` للمنسدلات والتنبيهات والخلفيات.
- `--ui-motion-slow: 240ms` للوحات السفلية والقائمة الجانبية.
- `--ui-ease-out` للظهور، `--ui-ease-in` للاختفاء، `--ui-ease-in-out` للانتقال بين حالتين.
- دخول الصفحة: `opacity` + `translateY(6px)` لمدة 240ms، ويُطبَّق على جذر الصفحة داخل `ptr__content` كي لا يتعارض مع سحب التحديث.
- `@media (prefers-reduced-motion: reduce)` يعطّل الحركة والانتقالات، ويبقى فهم الحالة ممكناً بدونها.

## 4) طبقة الهاتف

| العنصر | القرار |
| --- | --- |
| شريط التنقل | داكن بتدرج `deep-forest → forest-black`، زوايا 18px، ظل واحد ثابت، بلا `backdrop-filter`. |
| التحديد النشط | خلفية `rgba(218,241,222,.12)` ونص `mint` وأيقونة أثقل، بدل تغيير الأبعاد. |
| زر الإجراءات | دائرة 52px بلون Mint وحلقة داكنة، دوران 45° عند الفتح، وحركة قصيرة فقط. |
| آمن الشاشة | `env(safe-area-inset-bottom)` في الشريط واللوحات، و`env(safe-area-inset-top)` في الشريط العلوي. |
| المحتوى | حشوة سفلية `calc(6.5rem + safe-area)` فلا يغطي الشريط آخر عنصر. |
| اللمس | `touch-action: manipulation`، أهداف ≥ 44px، وإلغاء حالات hover على الأجهزة اللمسية. |
| الحقول | 16px على الهاتف لمنع تكبير iOS. |
| الجداول | تتحول إلى بطاقات على الهاتف كما كانت، مع الحفاظ على كل الأزرار والإجراءات. |

## 5) المكونات والاتساق

- الأزرار: مكوّن واحد `src/components/ui/Button.jsx` + `.btn` في CSS. الحالات: default / hover / active / focus-visible / disabled / loading.
- منع الإرسال المتكرر: `loading` يعطّل الزر تلقائياً، والمنطق الحالي في الصفحات يمنع الطلب المكرر ويحرّر الحالة في `finally`.
- الحقول: `Field/Input/Select/Textarea` هي المصدر، مع رسائل خطأ مرئية و`aria-invalid`.
- الجداول: نفس مكوّنات الجدول الحالية، دون تغيير في الأعمدة أو البيانات.
- اللوحات والنوافذ: مكوّن `Modal` واحد، وعلى الهاتف يتحول إلى لوحة سفلية بحد أقصى `88dvh` و`overscroll-behavior: contain`.
- البطاقات: `.card` بحدود `16px` وظل ثابت، وبطاقات المؤشرات تحتفظ بألوان الحالة الدلالية.
- التنقل: `Sidebar` لسطح المكتب و`BottomNav` للهاتف، وكلاهما من نفس مصدر الألوان.

## 6) ما لم يتغيّر

- لا تغييرات على `server/`, `firestore.rules`, أو أي عقد API.
- لا تغييرات على `AuthContext`, `ProtectedRoute`, أو الصلاحيات.
- لا بيانات وهمية ولا تعديل على قيم المبيعات أو التسويات.
- الخط، اللغة العربية، واتجاه RTL كما هي.
- سطح المكتب لم يُعاد تصميمه؛ تحسّن فقط ليتسق مع التوكنات الجديدة والحدود والزوايا.

## 7) التحقق

- `node --test test/designSystem.test.js` — 8 اختبارات للتوكنات والهوية والحركة والهاتف.
- `npm test` — كامل حزمة الاختبارات الحالية.
- `npm run build` — بناء Vite ناجح.
- اختبارات `uiAudit` الخاصة بالهاتف ما زالت تمر: لوحة الإجراءات السريعة، أزرار الإجراءات، والنوافذ المنبثقة.

## 8) قواعد التوسع

1. لا تُكتب قيمة لون جديدة داخل صفحة؛ استخدم `var(--ui-*)` أو اسم Tailwind المعرّف مركزياً.
2. أي مكوّن جديد يعيد استخدام `Button`/`Field`/`Card`/`Modal` قبل إنشاء بديل.
3. أي حركة جديدة تستخدم توكنات المدة والمنحنيات، وتُختبر مع `prefers-reduced-motion`.
4. لا تُضاف مكتبة رسوم أو حركة دون قياس أثر الحزمة والأداء.
5. أي استثناء بصري يحتاج سبباً موثقاً هنا بدل أن يصبح نمطاً موازياً.

## 9) حدود معروفة

- اختبار التباين تم حسابياً على قيم التوكنات (وليس عبر أداة خارجية أو قارئ شاشة حقيقي).
- لم يُجرَّب على جهاز iOS/Android فعلي في هذه البيئة؛ تم التحقق بالبناء والاختبارات الثابتة.
- إشعار لحظي واحد في `Layout` يستخدم ألواناً زرقاء دلالية قديمة ولم يُغيّر لأنه سلوك تنبيه مستقل عن الهوية؛ يمكن توحيده لاحقاً في مهمة منفصلة.
- بطاقات لوحة التحكم تحتفظ بتدرج داكن خاص بها، لكنه مبني الآن على ألوان الهوية الخضراء.

## 10) تحديثات الاحترافية (هذه الدفعة)

- درج القائمة الجانبية يقفل تمرير الخلفية، ويُغلق بـ `Escape`، ويُغلق تلقائياً عند تغيير المسار.
- لوحة الإجراءات السريعة تستخدم نفس قفل التمرير المشترك `src/lib/useBodyScrollLock.js` دون تعارض مع قفل `Modal`.
- رُفع `z-index` خلفية الدرج إلى 44 لتغطية شريط التنقل السفلي أثناء الفتح.
- قنوات RGB مركزية (`--ui-*-rgb`) لكل الظلال والحدود الشفافة، فلا تُكتب ألوان شفافة عشوائية.
- شاشة الخطأ العامة في `main.jsx` تستخدم توكنات الهوية بدل ألوان ساخنة قديمة.

## 11) إعادة تخطيط لوحة التحكم الرئيسية (وفق مرجع هيكلي)

المرجع البصري استُخدم كإطار تخطيط فقط، ولم تُنسخ ألوانه أو خطه أو نصوصه أو أرقامه. الهوية والألوان والتسميات والعملة بقيت من المشروع.

| منطقة المرجع | ما يقابلها في كروتك | مصدر البيانات |
| --- | --- | --- |
| Welcome / identity | شريط ترحيب مضغوط: الأحرف الأولى، اسم المدير، حالة الاتصال، وحداثة البيانات | `AuthContext` + `useOnlineStatus` + `DataFreshness` |
| Primary balance card | بطاقة "إجمالي المبيعات" + عمولة غير مسوّاة + عدد الشبكات | `stats.totalSales` / `totalCommissionOutstanding` / `totalUsers` |
| Four quick actions | إدارة المستخدمين، المبيعات والعمولات، إرسال إشعار، مركز القوالب | مسارات موجودة فقط |
| Grouped service tiles | ست خدمات: الواردة، الصادرة، المحافظ، الإصدارات، التسوية، الإعدادات | مسارات موجودة فقط |
| Savings/progress | "تسوية عمولة الإدارة": المسوّى من المستحق ونسبة محسوبة | `totalCommissionDue` و`totalCommissionOutstanding` |
| Recent transactions | آخر 8 مبيعات مع الحالة والتاريخ والعميل والمبلغ | `recentOperationsFromNetworks` |
| Bottom navigation | نفس شريط التنقل الحالي دون أي مسار جديد | `BottomNav` |

قرارات إضافية:

- أدوات صيانة الملخصات (إجراء متقدم) نُقلت إلى نهاية الشاشة داخل `<details>` بدل أن تدفع المحتوى الأساسي للأسفل؛ الوظيفة والتحقق والحالات محفوظة كما هي.
- لا توجد بيانات عرض وهمية، ولا مؤشرات نمو مصطنعة؛ النسبة الوحيدة معروضة هي نسبة تسوية حقيقية من المجاميع.
- تسميات الأقسام لا تُقصّ بـ line-clamp؛ البطاقات رأسية وقابلة للتمدد مع الترجمة الأطول.
- شبكة الخدمات: عمودان على الهاتف، ثلاثة على التابلت، وستة على الشاشات الواسعة؛ وبطاقات الإجراءات أربع في صف واحد.
- اختبارات الهيكل والبيانات في `test/dashboardLayout.test.js`.
